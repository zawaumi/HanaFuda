# AI駆動開発日記

このディレクトリには、HanaFudaで「何を作り、なぜそうしたか」を日ごとに記録します。チャットの全文やコマンドログではなく、チームが後から判断を追える短い開発記録を残します。

## ファイル名

日本時間の日付で1日1ファイルとします。

```text
docs/dev-diary/
├─ README.md
├─ 2026-09-20.md
└─ 2026-09-21.md
```

## 記録するタイミング

- 機能を実装・変更したとき
- 環境構築や設定を変更したとき
- 仕様や設計を決めたとき
- バグを調査・修正したとき
- テストや検証を行ったとき
- 実装しなかった場合でも、重要な調査結果や判断が残ったとき

原則として、作業と同じブランチ・コミットに日記の追記を含めます。

## エントリー形式

```markdown
## HH:MM — 短い作業名

- 担当: 人またはAIの名前
- ブランチ: `feature/example`
- 目的: 今回達成しようとしたこと
- 実施:
  - 変更した内容
  - 追加した内容
- 判断:
  - 決めたことと、その理由
- 変更箇所:
  - `path/to/file`
- 確認:
  - `npm run check` — 成功
- 次:
  - 残作業、注意点、または「なし」
```

項目に該当する内容がない場合は「なし」と書くか、その項目を簡潔にまとめます。

## 書かないもの

- APIキー、トークン、パスワード、`.env` の実値
- 不要な個人情報
- チャット全文
- 巨大なビルドログやコマンド出力
- 根拠のない推測

既存の記録は削除・改変せず、訂正が必要な場合は新しいエントリーとして追記します。
